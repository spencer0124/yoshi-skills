# 글 규칙

UI 와 무관한 글의 규칙. 규칙마다 ID 가 있고, ID 는 `lint.py` 의 검출 코드와 1:1 로 맞는다.
`lint.py` 가 뱉은 ID 를 여기서 찾아 처방대로 고친다.

- **F** 서식, AI 말투 제거
- **K** 한국어 문장
- **S** 구조, 표, 불렛
- **P** 절차 문서에만 걸리는 것
- **D** 판단 문서에만 걸리는 것
- **H** 사람만 판단할 수 있는 것 (린터가 못 잡는다. 마지막에 직접 확인한다)

등급은 두 가지다.

| 등급 | 뜻 | 린터 동작 |
|---|---|---|
| S1 | 1회만 나와도 실패 | 매 건 보고 |
| S2 | 빈도 초과부터 실패 | 문서, 블록 단위로 세어 한계 초과 시 보고 |
| S3 | 문서 자체를 기준으로 판정 | 중앙값, 비율로 재어 문서 크기와 무관하게 적용 |

**숫자를 두 부류로 나눈다.** 화면 폭(표 열 4개), 작업기억(리스트 7개, 한 문장 40~50자),
헤딩 깊이(H3)는 물리 상수다. 문서가 길어져도 안 변하므로 절대값으로 둔다.
섹션 수, 도표 수, 목차 유무는 문서 형태라서 문서 자체를 기준으로 잰다(S3). 그래서
섹션 20개짜리 절차서도 섹션들이 고르면 통과하고, 섹션 3개짜리 노트도 하나가 한 줄이면 실패한다.

출처: blader/humanizer, Wikipedia:Signs of AI writing, epoko77-ai/im-not-ai(AI 티 40패턴, KatFishNet),
DaleSeo/korean-skills(humanizer, style-guide, grammar-checker), toss/technical-writing,
이오덕 『우리글 바로쓰기』, 김정선 『내 문장이 그렇게 이상한가요?』,
Google developer documentation style guide, Microsoft Writing Style Guide, Nielsen Norman Group,
GOV.UK content design, Diátaxis, Amazon 6-pager.

## 0. 손대지 않는 것

규칙보다 앞선다. 아래는 문장이 어색해 보여도 원문 그대로 둔다. 자연스러운 한국어를 만들다가
용어를 바꾸면 문서가 읽기는 좋아지고 쓸모는 없어진다.

**원문 유지 대상**

- 기술 용어, 표준 약어: `API`, `prompt`, `token`, `alias`, `backfill`, `promote`, `rollback`, `staging`, `RC`, `LLM`, `GPU`
- 코드 식별자, 경로, 명령어, 환경 변수, 필드명, 리비전 번호: `docker-compose.prod.yml`, `IMAGE_TAG`, `aq_eligible`, `078`
- 제품, 서비스, 저장소, 브랜치 이름: `npcat`, `np-enterprise`, `dev`, `main`
- 팀이 이미 쓰는 사내 용어. 회의와 PR 에서 부르는 그 이름으로 쓴다
- 수치, 날짜, 단위, 인용문

**하지 않을 일**

- 기계적 직역. `prompt` 를 "지시문", `token` 을 "표식", `promote` 를 "승격 처리" 로 바꾸지 않는다
- 정착된 영어 용어를 한국어로 풀어 쓰기. "RC 컷" 을 "릴리즈 후보 절단" 으로 바꾸지 않는다
- 같은 개념을 문서 안에서 두 이름으로 부르기. 원문 용어 하나를 골랐으면 끝까지 그 이름이다

**판별**

팀이 말할 때 쓰는 말인가. `staging` 을 "준비 환경" 이라 부르는 사람이 팀에 없으면 `staging` 으로 쓴다.
번역이 의미를 좁히거나 넓히면 원문이 맞다. 영어 표기가 광고성 수사(`seamless`, `robust`, `leverage`)일
때만 한국어로 푼다(im-not-ai B-2).

**적용 순서**

용어는 원문, 문장은 한국어다. "alias 에 대한 검증을 수행합니다" 에서 고칠 것은 `alias` 가 아니라
"에 대한" 과 "수행합니다" 다. 결과는 "alias 를 검증한다" 다.

이 원칙은 린터가 검사하지 않는다. 고칠 때마다 사람이 지킨다.

## 1. 서식 (F)

강조는 표기가 아니라 자리로 만든다. 첫 화면, 콜아웃, 표의 첫 열이 강조 장치다.

**F-01 강조 태그 금지 (S1)**
`<b> <strong> <i> <em> <mark> <u>` 를 본문에 쓰지 않는다. 눈에 띄어야 하는 문장은 콜아웃으로 올리거나 섹션 첫 줄에 둔다.

**F-02 마크다운 잔재 금지 (S1)**
`**굵게**`, `__밑줄__` 이 HTML 안에 남으면 안 된다. artifact 는 HTML 이다.

**F-03 이모지 금지 (S1)**
헤딩, 불렛, 구분 기호로 이모지를 쓰지 않는다. 허용은 콜아웃 `<span class="icon">` 하나뿐이다. 칼럼, 리포트 장르의 이모지는 AI 신호다(im-not-ai C-5).

**F-04 대시 금지 (S1)**
`—` `–` 를 연결어로 쓰지 않는다. 마침표로 끊거나 쉼표, 괄호로 바꾼다. 영어 em dash 강조 문체의 직수입이다(im-not-ai J-3, DaleSeo 패턴 6).

**F-05 화살표 위치 제한 (S1)**
`→` 는 표 셀과 코드 주석 안에서만. 문장에서는 "12,000원에서 9,900원으로 내린다" 로 쓴다.

**F-06 직선 따옴표 (S1)**
`" "` 를 쓰고 `“ ” ‘ ’` 는 쓰지 않는다. 따옴표 강조 5회 이상은 그 자체가 AI 신호다(im-not-ai J-2). 인용이 아니면 따옴표를 빼고 평어로 쓴다.

**F-07 인라인 색 금지 (S1)**
`style="color:…"` 같은 직접 지정을 하지 않는다. 라이트, 다크 대응은 `notion.css` 가 한다.

**F-08 헤딩 깊이 H3 (S1)**
H4 가 필요하면 페이지를 나눈다(Google).

**F-10 가운뎃점 금지 (S1)**
`·` `•` `・` `ㆍ` 를 쓰지 않는다. 열거는 쉼표로, 제목의 구분은 문장이나 헤딩으로 나눈다.
"쿠키, 세션, 토큰" → "쿠키, 세션, 토큰". "값 변화, 54건" → "값 변화 54건".
맞춤법상 가운뎃점은 짝을 이루는 어구에만 쓰지만(한글 맞춤법 문장 부호), 이 스킬은 전부 금지한다.
단순 나열을 가운뎃점으로 묶는 습관이 AI 표기 신호로 읽힌다.

**F-11 콜아웃 안 불렛 금지 (S1)**
콜아웃에 `<ul>` `<ol>` 을 넣지 않는다. 콜아웃은 한두 문장이다. 목록이 필요하면 그것은 콜아웃이 아니라 섹션이다.

**F-12 콜아웃 연속 금지 (S1)**
콜아웃 두 개를 붙여 놓지 않는다. 사이에 본문이 없으면 독자는 둘 다 안 읽는다. 하나로 합치거나 사이에 문단을 둔다.

**F-09 라벨 굵게+콜론 불렛 금지 (S1)**
`요금: 9,900원으로 내린다` 형태의 불렛을 쓰지 않는다. 라벨이 필요한 내용은 표의 첫 열로 옮긴다.

## 2. 한국어 문장 (K)

### 2.1 번역투 조사, 구문

**K-12 "~에 대해/에 대한" (S2, 문서 1회)**
목적격 조사로 직결한다. "alias 에 대해 설명" → "alias 를 설명". 의견, 태도의 대상일 때만 남긴다.

**K-13 "~를 통해/통하여" (S2, 문서 1회)**
"~로", "~해서", "~함으로써" 로 분산한다. "스크립트를 통해 만든다" → "스크립트로 만든다".

**K-14 "~와 관련된/관련하여" (S2, 문서 1회)**
"~에", "~의" 로 줄이거나 실제 관계를 동사로 쓴다. "요금과 관련된 값" → "요금 값".

**K-15 "~에 기반하여/바탕으로" (S2, 문서 1회)**
"~로", "~을 보고" 로 바꾼다.

**K-02 "~에 있어(서)" (S1)**
"~에서", "~을 볼 때" 로 바꾼다. 한 번만 나와도 결정적 신호다(im-not-ai A-3).

**K-03 "가지고 있다" (S1)**
have 동사 직역. "경쟁력을 가지고 있다" → "경쟁력이 강하다".

**K-16 "~에 의해" (S1)**
행위자를 주어로 올린다. "스크립트에 의해 생성된 값" → "스크립트가 만든 값".

**K-06 추상 주어 + 만능 동사 (S1)**
"이 문서는 값의 변화를 보여준다" 같은 문장을 쓰지 않는다. 도구, 시스템, 시대를 주어로 세우지 않는다(toss). 동작 설명이 목적일 때만 도구가 주어가 된다.

**K-28 영어식 대명사 주어 (S1)**
"그것은", "이것은", "이는" 을 삭제한다. 한국어는 주어를 생략하는 언어다. 선행 명사구가 애매하면 명사를 복원한다.

**K-29 불필요한 '-들' (S2, 문서 1회)**
수식어나 문맥이 복수를 말하면 뺀다. "많은 사용자들" → "많은 사용자", "기능들을 늘린다" → "기능을 늘린다".

**K-39 영어 병기 반복 (S2, 문서 1회)**
한글(영어) 병기는 첫 등장 1회만. 이후는 한글로만 쓴다.

### 2.2 피동, 가능, 목적

**K-01 이중 피동 (S1)**
"되어진다", "나뉘어진", "잊혀지지", "보여질" 을 쓰지 않는다. 능동이나 단일 피동으로. 능동태를 먼저 고른다. "저장된다" 보다 "저장한다".

**K-17 "~할 수 있다" 남발 (S2, 문서 2회)**
실제 가능성을 말할 때만 쓴다. 나머지는 단정으로 바꾼다. "지울 수 있다" → "지운다". 다만 원래 유보였던 문장을 단정으로 올리지 않는다.

**K-18 "~을 위해" 목적절 (S2, 문서 1회)**
"~려고", "~도록" 으로 바꾼다.

**K-24 진행형 "~고 있다" (S2, 문서 1회)**
단순 시제로 환원한다. "늘고 있다" → "늘었다".

**K-25 완곡 중첩 (S2, 문서 1회)**
"할 수 있을 것으로 보인다" → "할 수 있다" 또는 "한다". 완곡은 하나만 남기고, 남긴 완곡의 확신 강도는 원래대로 둔다. 추측을 단정으로 승격하지 않는다.

### 2.3 형식명사, 명사화

**K-20 "~것이다" (S1)**
미래 단정과 형식 종결을 쓰지 않는다. "내려갈 것이다" → "내려간다".

**K-21 "~하는 것" (S1)**
"측정하는 것이 필요하다" → "측정한다". 형식명사를 동사로 되돌린다.

**K-19 "~는 점에서 / 주목할 점은" (S1)**
"값이 같다는 점에서 유지한다" → "값이 같아서 유지한다". "X는 ~다" 직설로.

**K-22 "~적 N" 추상 체인 (S2, 블록 1회)**
"구조적 한계" → "구조의 한계", "전략적 함의" → "전략 차원의 의미". 정착된 용어(전략적 파트너십)는 예외다.

**명사 나열 금지 (H, 린터 불가)**
"alias 생성 규칙 적용 대상 변경" → "alias 규칙을 적용하는 대상이 바뀐다". 동사에서 파생된 명사(설정 수행, 검토 진행)를 쓰지 않는다(toss).

### 2.4 어휘, 상투구

**K-04 결산, 예열 상투구 (S1)**
"결론적으로", "요약하면", "정리하면", "시사하는 바가 크다", "주목할 만하다", "의미가 크다", "살펴보자", "이상입니다", "도움이 되길" 을 쓰지 않는다. 결론은 상투구 없이 그대로 쓴다.

**K-05 결말 공식 (S1)**
"~할 때다", "지금이야말로", "~인 셈이다", "~라는 뜻이다", "~하는 이유다" 도치를 쓰지 않는다. 순방향 평서로 닫는다.

**K-07 메타 담화, 열거 도입 (S1)**
"이 문서에서는", "아래에서 설명한다", "크게 세 가지로", "다음과 같은" 을 삭제하고 본론부터 쓴다(toss, im-not-ai D-3).

**K-08 챗봇 잔재 (S1)**
"좋은 질문", "물론입니다" 를 쓰지 않는다.

**K-09 대비 구문 (S1)**
"A가 아니라 B다", "~것이 아니라", "단순한 X를 넘어 Y" 를 쓰지 않는다. Y 만 단언한다. 사람 글 실측 0건 패턴이다(im-not-ai A-21, C-8).

**K-10 hype 어휘 (S1)**
"혁신적", "획기적", "압도적", "전례 없는", "강력한", "놀라운" 을 구체 수치로 바꾼다. "압도적 성장" → "전년 대비 47% 성장".

**K-26 강조 부사 (S1)**
"매우", "정말", "상당히", "굉장히", "너무" 를 삭제한다. 강조는 수치가 한다.

**K-27 불필요한 한자어 (S1)**
"수행한다", "실시한다", "진행한다", "처리를 한다" 를 "한다" 로 줄인다. "삭제를 수행한다" → "삭제한다"(toss, 이오덕).

**K-40 사전 은유, 상투 비유 (S1)**
"잠식", "청사진", "적신호", "신호탄", "뿌리내린다", "기록적" 을 명제로 직역한다. "잠식한다" → "점유율을 뺏는다". 사람 코퍼스 0건 패턴이라 오탐이 없다(im-not-ai D-14).

**근거 없는 권위 인용 금지 (H)**
"전문가들은", "일반적으로 알려진" 을 쓰지 않는다. 출처가 있으면 출처를, 없으면 문장을 지운다.

### 2.5 리듬, 문체, 부호

**K-31 문장 길이 (S1, 60자 초과)**
한 문장 한 생각, 40~50자를 노린다. 길면 자른다. 단 모든 문장을 같은 길이로 맞추지 않는다. 짧은 문장 사이에 긴 문장이 한 번 섞이는 것이 사람의 리듬이다(im-not-ai E-1).

**K-32 경어체 혼용 금지 (S1)**
결정 문서는 평서체 "~다" 로 고정한다. "~합니다", "~해요", "~세요" 를 섞지 않는다.

**K-33 지칭 통일 (S1)**
"우리" 와 "저희" 를 섞지 않는다. "우리" 로 쓴다.

**K-34 같은 종결어미 4연속 (S2)**
"~한다" 가 네 문장 연달아 오면 하나를 명사 종결이나 다른 어미로 바꾼다(KatFishNet 리듬 신호).

**K-23 문두 접속사 (S2, 문서 2회)**
"또한", "따라서", "즉", "게다가" 로 문장을 시작하는 횟수를 제한한다. 논리 관계는 문장 자체가 말한다.

**K-30 연결어미 뒤 쉼표 (S1)**
"값을 지우고, 표를 나눈다" 의 쉼표를 뺀다. 영어 접속사 쉼표의 직수입이며 KatFish 분리도가 가장 높은 부호 신호다(im-not-ai C-11). 윤문 후 개수가 늘면 실패로 본다.

**K-37 문장 끝 콜론 (S1)**
"바뀌는 값:" 같은 도입 콜론을 쓰지 않는다. 마침표로 끝내거나 헤딩으로 올린다.

### 2.6 표기

**K-35 날짜 (S1)**
`2026-09-16` 한 형식. "2026년 9월", "2026.09.16" 을 섞지 않는다.

**K-36 숫자, 단위 띄어쓰기 (S2)**
문서 안에서 한 방식으로. "54건", "22GB" 처럼 붙이거나 전부 띄거나 하나만 고른다. 숫자는 아라비아 숫자로.

**용어 통일 (H)**
0절이 먼저다. 기술 용어는 원문 그대로 쓴다. 같은 개념은 한 이름. "자산" 과 "asset" 을 섞지 않는다. 코드 식별자만 `<code>` 로 구분한다. 약어는 첫 등장에 풀어 쓴다. 외래어 표기는 업계에서 많이 쓰는 형태를 따르고 문서 안에서 고정한다(toss).

---

## 3. 구조 (S)

### 3.1 결론 먼저

**S-01 `<title>` (S1)**
명사구 2~4 단어. 문장으로 끝내지 않는다.

**S-02 페이지 제목 (S1)**
`h1.title` 1개.

**S-03 결론 콜아웃 (S1, reference 면제)**
첫 블록이 결론 콜아웃이다. 필드표, 스펙 같은 `reference` 문서는 결론이 없으므로 면제다. 콜아웃 총 3개까지(결론 1 + 주의, 확인 2). 독자는 본문의 20~28% 만 F 자로 훑는다(NN/G). 결론과 권고를 맨 위에, 근거를 아래에 둔다(Minto, GOV.UK 역피라미드).

**S-04 (삭제됨)**
"펼친 섹션 3개 이내" 는 문서 길이와 무관한 고정 개수라서 참조 문서와 절차서를 무조건 실패시켰다.
S-18 섹션 균형이 대신한다. 개수가 아니라 섹션끼리 분량이 고른지를 본다.

**S-12 헤딩 위계 (S1)**
레벨을 건너뛰지 않는다. 헤딩 아래 내용 없이 헤딩이 이어지지 않는다.

**S-13 헤딩 문형 (S1)**
내용을 말하는 명사구로 쓴다. "개요", "소개", "정리", "결론" 같은 일반 명칭과 질문형을 쓰지 않는다. 같은 층 헤딩은 같은 문형으로(Microsoft). 헤딩 아래 첫 문장이 헤딩을 반복하지 않는다.

### 3.2 불렛

**S-08 리스트 크기 (S1)**
항목 1개짜리 리스트 금지(문장으로 푼다). 항목은 7개까지(Miller 7±2).

**S-09 중첩 깊이 (S1)**
불렛은 2단까지, 토글 안 토글 금지. 3단이 필요하면 상위를 헤딩이나 표로 승격한다. 토글 안 토글은 발견율을 절반으로 떨어뜨린다(NN/G).

**S-10 문형 일치 (S1)**
한 리스트 안에서 전부 명사구이거나 전부 문장이다. 상위 불렛은 짧은 명사구 라벨, 하위 불렛에 사실을 쓴다.

**리스트 선택 (H)**
순서, 우선순위, 의존이 있으면 번호, 없으면 불렛(Google). 인과와 논증은 리스트가 아니라 문단으로 쓴다(NN/G, Amazon 6-pager). 리스트 앞 도입 문장은 완결문이다.

### 3.3 표

**S-05 표 크기 (S1)**
열 4개 이내. 본문 폭 708px 이 물리 한계라 문서 길이와 무관하게 절대값이다.
펼친 표는 본문 행 8개 이내(NN/G 비교표 한계). `<details>` 로 접은 표는 행 제한이 없다.
읽을 사람이 펼치기로 선택한 표는 길어도 된다.

**S-06 표 형태 (S1)**
1행, 1열 표 금지, 병합 셀 금지, 빈 셀 금지. 빈 칸에는 "동일", "해당 없음" 을 쓴다(Google, Microsoft).

**S-07 셀 길이 (S1)**
셀은 한 줄, 40자 이내, 문장을 넣지 않는다. 길면 토글이나 본문으로 뺀다.

**표를 쓸 조건 (H)**
행마다 관련 값이 3개 이상일 때만 표를 쓴다. 값이 1~2개면 리스트다. 한 열의 셀은 같은 품사로 채운다. 행 식별자는 맨 왼쪽 열, 헤더는 첫 행과 첫 열만.

**As-is / To-be (H)**
속성은 행, 대안은 열. 첫 열이 축 이름, 둘째 열 As-is, 셋째 열 To-be. 순서를 바꾸지 않는다. 두 열을 같은 층위로 채우고, 변화 없는 축은 "동일" 로 쓴다. 표 앞뒤에 각 대안의 실제 예시를 1개씩 둔다.

### 3.4 점진적 공개

**S-11 구분선 (S1)**
`<hr>` 은 본문과 접힌 상세 사이 1번만.

**토글 제목 (H)**
내용과 규모를 말한다. "값 변화, 54건 중 22건" 처럼 숫자를 붙인다. 결론, 비교, 예시는 펼치고, 전체 목록, 소비처 표, 출처는 접는다.

---

### 3.5 헤딩

**S-14 본문 h1 금지 (S1, note/decision)**
페이지 제목 `h1.title` 하나만 h1 이다. 본문 헤딩은 h2 부터 시작한다.
`procedure` 와 `reference` 는 길어서 h1 로 큰 덩어리를 나눠도 된다.

**S-15 형제 없는 h3 금지 (S1)**
h2 아래 h3 가 하나뿐이면 그것은 헤딩이 아니다. 문장으로 내리거나, 빠진 짝을 찾는다.
하나를 나누면 둘이 되지, 하나가 되지 않는다.

**S-16 헤딩 20자 이내 (S1)**
헤딩이 길어지는 것은 내용을 못 줄였다는 뜻이다. 목차에서 잘려 보이기도 한다.

**S-17 참조 문서의 목차 (S1, reference)**
`reference` 이고 펼친 헤딩이 6개를 넘으면 `<nav class="toc">` 를 둔다.
목차 내용은 `template.html` 의 스크립트가 헤딩에서 만든다. 손으로 쓰지 않는다.
실제 헤딩 레벨이 건너뛰어도(h1 다음 h3) 목차 들여쓰기는 한 단씩만 내려간다.

### 3.6 균형과 밀도

**S-18 섹션 균형 (S3)**
섹션 개수는 안 센다. 펼친 h2 마다 본문 블록 수를 재서 중앙값과 비교한다.
중앙값의 1/3 미만이면 쪼가리 섹션이다. 옆 섹션에 합치거나 문장으로 내린다.
중앙값의 3배를 넘으면 혼자 비대한 섹션이다. 나누거나 상세를 `<details>` 로 접는다.

**S-19 시각 블록 예산 (S3)**
표, 코드 블록, 도표의 합이 본문 블록에서 차지하는 비율에 한계가 있다.
`note` 와 `decision` 은 30%, `procedure` 는 45%, `reference` 는 면제다.
넘으면 설명 문단이 모자란 것이다. 표를 합치거나 문단을 늘린다.

**S-20 도표 캡션 (S1)**
`<figure>` 에는 `<figcaption>` 이 있어야 한다. 캡션은 제목이 아니라 **읽는 법**이다.
"전체 구조" 가 아니라 "왼쪽에서 오른쪽으로 값이 한 번만 바뀐다" 로 쓴다.
캡션을 못 쓰겠으면 그 도표는 독자에게 줄 것이 없다. 뺀다.
도표는 mermaid 로 그린다. ASCII 도표는 쓰지 않는다.

## 4. 절차 문서 (P)

**P-01 단계 안 토글 금지 (S1)**
`<ol>` 안에 `<details>` 를 넣지 않는다. 절차를 따라가는 사람은 접힌 단계를 건너뛴다.
단계가 길면 접는 게 아니라 나눈다.

**P-02 롤백 섹션 필수 (S1)**
헤딩에 롤백, 되돌리기, 복구, 실패 중 하나가 있어야 한다.
되돌리는 방법이 없는 절차는 절차가 아니라 도박이다.

---

## 5. 판단 문서 (D)

**D-01 선택지 필수 (S1)**
비교 표(열 3개 이상)나 대안 섹션이 있어야 한다.
대안이 없으면 그것은 판단이 아니라 통보다. 통보면 `note` 로 쓴다.

**D-02 장애 기록의 후속 조치 (S1)**
타임라인(시각 3개 이상)이 잡히면 헤딩에 후속 조치, 재발 방지, 조치 중 하나가 있어야 한다.
무슨 일이 있었는지만 적고 끝내지 않는다.

## 6. 사람이 확인할 것 (H)

린터를 통과해도 아래가 틀리면 문서는 실패다. publish 직전에 직접 읽고 확인한다.

- 첫 콜아웃이 진짜 결론인가. 요약이나 배경이 아니라 독자가 내려야 할 판단인가.
- 표의 축이 독자의 결정 기준인가. 만들기 쉬운 축을 고르지 않았는가.
- 예시가 실재하는 값인가. 응답값, 코드를 지어내지 않았는가.
- 측정값과 추정을 구분했는가. 추정에는 "추정", "미확인" 을 붙였는가.
- 접은 것과 펼친 것의 선택을 의식적으로 했는가.
- 숫자, 고유명사, 인용을 원자료 그대로 옮겼는가.
- 다크 모드에서 읽히는가.

## 7. 출처 간 충돌과 이 스킬의 선택

원 출처들은 서로 어긋난다. 이 스킬은 아래로 정한다.

| 쟁점 | 출처 A | 출처 B | 이 스킬 |
|---|---|---|---|
| 한자어, "~적" | 전면 금지(이오덕) | 선택적 제거(toss) | 선택적 제거. K-22, K-27 만 강제 |
| 이모지, 구어체 | 장르별 허용(DaleSeo) | 전면 금지(im-not-ai) | 콜아웃 아이콘 외 금지 |
| 문체 변주 | 격식체에 비격식체 섞기(DaleSeo) | 격식 등급 고정(im-not-ai E-7) | 평서체 "~다" 고정 |
| 띄어쓰기 | 자연스러운 변동 도입(DaleSeo) | 규범 준수 | 규범 준수. 변동은 만들지 않는다 |
| 번역투 빈도 | 3회+ 부터 신호(im-not-ai) | 1회도 교정(humanizer) | 결정 문서는 짧다. S1 은 0회, S2 는 문서 1~2회 |
| 리스트 | 리스트가 주목도 3배(NN/G) | 연속 불렛은 AI 신호(im-not-ai C-2) | 불렛 블록 3개 연속 금지, 인과는 문단으로 |

im-not-ai 의 빈도 기준은 5,000자 칼럼을 전제한다. 이 스킬의 결과물은 한 화면 분량이라 같은 밀도면 훨씬 진해 보인다. 그래서 한계를 문서 1~2회로 조인다.
